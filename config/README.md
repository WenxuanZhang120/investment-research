# 配置文件说明

本目录保存稳定、非敏感且需要版本控制的项目规则。账号、密码、令牌和其他凭据不得写入这里。

## `project.toml`

保存项目名称、时区、目录路径、原始数据保护原则和数据血缘字段要求。当前配置 schema 版本为 2。

标准化记录的血缘分为两层：

- 记录层保存来源、抓取时间、原始记录 ID、原始快照路径、标准化器版本和映射版本；
- `field_lineage` 为每个标准字段保存原始字段名、标准字段名和解析器版本等字段级证据。

## `field_mappings.json`

保存 iWencai 原始基础字段名到标准字段名的映射。映射文件使用 JSON，以便当前 Python 3.8 环境直接通过标准库读取，不需要安装第三方 TOML 或 YAML 解析器。

每项映射包括：

- `canonical_field_name`：系统内部使用的稳定字段名；
- `category`：字段类别；
- `raw_base_fields`：iWencai 可能返回的原始基础字段名列表。
- `statement_type`：财务事实所属的利润表、资产负债表或现金流量表；
- `value_nature`：财务事实是期末时点值 `instant`，还是年初至报告期末累计值 `duration_ytd`；
- `unit`：仅在来源口径已经确认时记录标准单位。

示例：

```json
{
  "canonical_field_name": "close",
  "category": "market",
  "raw_base_fields": ["收盘价"]
}
```

## `daily_pipeline.json`

保存无 LLM 日常流水线的版本化执行顺序。阶段固定为状态检查、标准化、衍生计算、报告和最终验证。

`input_readiness` 将财务采集任务显式分为基础指标输入和高级指标输入。运行前，`scripts/resolve_daily_pipeline.py` 只读取本地 Raw 快照、标准化清单和衍生清单，并按完整分页集合、原始记录 ID、映射版本和计算版本判断是否需要处理：

- 原始分页不完整时，标准化和衍生计算保持跳过；
- 完整且尚未标准化时，加入一次标准化步骤；
- 已标准化但对应版本指标尚未生成时，加入一次衍生步骤；
- 相同输入和处理版本已经存在时，标记为 `up_to_date`，不重复覆盖。

解析出来的路径和执行命令只使用仓库相对路径。配置中的任务 ID 必须来自版本化财务采集计划，不能通过文件日期猜测输入身份。

当前配置明确设置 `llm_calls_allowed = false` 和 `external_collection_enabled = false`。因此默认运行只读取现有仓库、检查采集计划状态、执行系统完成度审计和仓库验证，不会调用 iWencai。未来启用采集必须经过独立审查，并继续保证 Python 确定性运行、Raw 先保存和失败即停止。

## 修改规则

1. 原始字段名必须精确保留，不得先翻译或改写。
2. 新增或调整映射时必须更新 `mapping_version`。
3. 一个原始基础字段只能映射到一个标准字段。
4. 不确定的字段不得猜测映射，应保留为 `unmapped`。
5. 单位和复权口径只有在来源明确时才能加入映射。
6. 每次修改映射都必须增加对应的自动测试。

## 检查字段解析结果

解析器只处理字段名称，不读取或修改数据值，也不会发起网络请求：

```bash
python3 scripts/parse_iwencai_fields.py \
  "收盘价[20260807]" \
  "归母净利润[2026一季报]" \
  --pretty
```

输出会同时保留 `raw_field_name`，并记录标准字段名、日期或报告期、映射版本、解析器版本和置信度。无法识别的字段会标记为 `unmapped`。

## 已确认的动态语义

`股票市场类型` 在不同问句中既可能返回单个值，也可能返回以分号分隔的多个市场归属标签。映射版本 2.0.0 将其统一映射为 `market_memberships`，标准化时始终保存为字符串数组，不假设它是单一交易所字段。交易所后缀从完整证券代码确定，并单独保存推导血缘。

映射版本 3.0.0 加入三大财务报表的基础事实和报告元数据。iWencai OpenAPI 实际返回的财务字段使用紧凑日期上下文，例如 `营业收入[20251231]`。对于 `financial` 和 `financial_metadata` 类字段，解析器将这个日期解释为 `period_end`，而不是市场数据的 `as_of_date`。同一日期在市场字段和财务字段中的语义因此保持明确区分。

`货币资金` 映射为 `monetary_funds`，不得与现金流量表的“现金及现金等价物”混为一项。银行等特殊行业未返回的存货、应收账款或货币资金保留为空值，不能补零。

映射版本 3.1.0 根据全市场查询新增 `total_equity`。`所有者权益` 与 `归母权益` 保持为两个标准字段，不因名称相近而合并口径；ROE 明确使用平均归母权益。

映射版本 3.2.0 加入 ROIC 和自由现金流所需的所得税费用、四类有息负债与购建长期资产现金支出。负债项目缺失时不得按零处理；只有来源明确返回零时才是零。

## `financial_metrics.json`

保存派生财务比率的版本化公式、分子、分母和分母约束。当前仅包含可以从同一报告期直接计算且无需年化的五项比率。修改公式或口径必须提升 `metric_definition_version` 并增加测试；缺失输入、零分母或不符合正值约束时保留空值和原因状态，不得补零或静默删除。

`advanced_financial_metrics.json` 保存跨期收入/利润增长、平均归母权益 ROE、平均投入资本 ROIC 和自由现金流公式。同比增长使用上年同期；ROE 和 ROIC 使用当前期末与本报告期年初（上年末）的平均余额。两类期间在年报中相同，在一季报、半年报和三季报中必须分别处理。ROIC 的投入资本逐项要求权益、有息负债和货币资金，不能用总负债替代。

`financial_collection_plan.json` 固定完成高级财务指标所需的五个问句及报告期。问句文本是原始数据身份的一部分，续采时不得改写；计划运行器会从已有不可变快照推导下一页，而不是人工记忆进度。

## `collection_safety.json`

保存人工财务采集入口的安全边界，包括允许任务白名单、凭据环境变量名、逐任务确认前缀、单次页数预算和请求超时。安全配置不保存密钥值。

`preflight` 只读取本地计划和 Raw 状态，不需要凭据，也不发起网络请求。真正采集必须同时满足：任务属于白名单、已有分页状态无错误、任务尚未完成、下一页可安全推导、存在 `IWENCAI_API_KEY`，并且确认文本精确等于 `COLLECT:<job_id>`。单次最多保存 60 页；达到预算但尚未结束时保留当前 Raw 段，下次从下一页继续。

## `event_taxonomy.json`

保存公告标题到事件类型的版本化关键词规则。分类只用于组织研究队列，不代表利好、利空或投资判断。规则按文件顺序匹配并保留实际命中的关键词；无法匹配的公告进入 `other_announcement`。规则变化必须提升 `taxonomy_version`。

版本 1.2.0 加入管理层变动，包括董事长/总经理辞职、聘任和高级管理人员变动。公告和新闻共用分类规则，但新闻分类只表示标题命中，必须由原始来源或公告验证。

## 组合与筛选规则

`portfolio_schema.json` 规定私密持仓、交易和投资卡的字段与允许状态；`portfolio_review_rules.json` 规定持仓复核类别的透明优先级；`screening_rules.json` 规定全市场初筛资格、因子方向、权重和研究优先级边界。

筛选配置的 `purpose` 固定为 `research_priority_only`。规则变化必须提升相应版本并重新生成批次。当前市场规则明确标记 `cross_industry_preliminary`，在行业数据就绪前不得把全市场百分位当作行业内可比结论。

## `research_workflow_schema.json`

规定研究状态、置信度、估值情景、允许的决策动作和最终决策权。系统固定 `final_authority = investor`，验证器拒绝把最终权限改为 AI。
