# Personal Investment Research System

这是一个长期建设的个人投资研究与决策支持系统。项目通过数据工程、结构化研究和投资复盘来提高决策质量，但不用于自动交易。

## 项目目标

系统最终形成以下协作方式：

- **Codex**：负责建设、测试、修复系统，并在当前阶段调度每日数据、公告和新闻采集。
- **Python + GitHub Actions**：负责确定性的 Raw 导入、标准化、验证和报告生成。
- **GitHub**：作为研究资料、数据文件、程序和变更历史的中央仓库。
- **iWencai（同花顺问财）**：作为主要的 A 股数据来源。
- **ChatGPT**：负责结构化投资分析、风险审查和投资委员会辅助。
- **投资者本人**：保留最终投资决策权并负责实际执行。

完整工作流预计为：

```text
Codex 每日采集调度
  ↓
数据来源工具
  ↓
Raw 原始响应
  ↓
Python 确定性数据管道
  ↓
GitHub 投资研究仓库
  ↓
结构化投资数据库
  ↓
ChatGPT 投资分析流程
  ↓
投资决策日志与组合复盘
```

Codex 负责 Build / Fix / Improve，并在当前阶段承担每日采集编排；Python 负责可重复的标准化与处理，ChatGPT 负责 Analyze，投资者负责 Decide。完整且具有约束力的职责边界见 [`ARCHITECTURE.md`](ARCHITECTURE.md)。

每日采集计划位于 `config/codex_daily_collection.json`，面向非技术使用者的流程说明见 [`每日自动采集说明.md`](每日自动采集说明.md)。当前股票范围限定为沪深主板，排除北交所、创业板和科创板；同时独立覆盖境内上市的纳斯达克 100／标普 500 ETF，详见 [`投资范围说明.md`](投资范围说明.md)。Codex 必须保存工具的未修改响应；Python 导入器 `scripts/import_codex_collection.py` 会复核原始字段、拒绝凭据字段、先写入不可覆盖的 Raw，再调用现有标准化器。外部工具调用仍与离线 Python 流水线分离，因此标准化结果可以复现，也不会让模型在数据行中自行补值。

Python 离线处理入口为 `python3 scripts/run_daily_pipeline.py`。其版本化配置位于 `config/daily_pipeline.json`；Python 自身的外部采集仍然关闭。运行前会自动检查本地 Raw 批次是否完整以及对应版本的标准化、衍生结果是否已经存在，只有就绪且未处理的任务才会加入执行计划。`--dry-run` 可在不执行任何步骤的情况下查看门控结论和完整计划。

同一入口也会按版本化查询路由发现本地公告与新闻 Raw，自动判断是否需要重新标准化，并生成不可变的 `reports/daily/monitoring/` 报告包。每个报告包包含事实索引、来源清单、来源清单哈希、报告哈希、时点覆盖和“无投资判断／无自动交易”标记。全市场筛选仅在完整市场与财务指标输入就绪、且对应规则版本尚未处理时运行。

`.github/workflows/daily-offline-pipeline.yml` 继续作为独立的只读复核任务，在工作日北京时间 18:00 运行离线入口。它不持有数据源凭据、不负责采集和推送；Codex 每日任务负责在本地完成采集、导入和验证，只有全部通过后才能发布仓库变更。

仓库仍保留旧的 `.github/workflows/manual-financial-collection.yml` 和 `IWENCAI_API_KEY` 采集代码，供历史审计与未来兼容检查；该入口目前没有可由用户配置的有效凭据，不属于新的每日运行路径，也不应被 Codex 定时任务调用。新的日常入口只接受 Codex 工具返回的无凭据采集产物。

真实采集成功后，工作流会先对产物执行只读导入预检。下载产物后，应先在本地重复预检，再由专用导入器把已经验证的 Raw 快照和查询日志以不可覆盖、可重复执行的方式写回仓库。导入报告只保存仓库相对路径和 Actions 运行身份，不保存下载目录、凭据或本机路径：

```bash
python3 scripts/import_financial_collection_artifact.py <下载后的产物目录> --dry-run
python3 scripts/import_financial_collection_artifact.py <下载后的产物目录>
python3 scripts/validate_repository.py
```

本地无网络预检示例：

```bash
python3 scripts/run_guarded_financial_collection.py \
  --action preflight \
  --job 2026q1_base_resume
```

## 目录职责

| 目录 | 未来职责 |
| --- | --- |
| `config/` | 配置文件、字段映射和其他规则文件。 |
| `data/raw/` | 保存数据源的原始响应。原始文件必须保留且不得覆盖。 |
| `data/normalized/` | 保存经过清洗和标准化的结构化数据。 |
| `data/derived/` | 保存计算指标、估值分位、风险指标等衍生数据。 |
| `portfolio/` | 保存持仓、交易记录和投资卡片。 |
| `reports/daily/` | 保存自动生成的每日研究报告。 |
| `reports/weekly/` | 保存每周市场和投资组合复盘报告。 |
| `reports/quarterly/` | 保存季度研究和投资组合复盘报告。 |
| `research_queue/` | 保存等待进一步研究的证券和主题。 |
| `decision_journal/` | 保存投资决策及后续复盘记录。 |
| `scripts/` | 保存未来的数据采集、标准化、处理和报告脚本。 |

## 核心设计原则

1. **先保存原始数据**：任何标准化或计算开始前，先完整保存数据源响应。
2. **原始数据不可覆盖**：未来采集的新快照不得破坏已有原始记录。
3. **字段必须可追溯**：iWencai 的原始动态字段名必须能追溯到标准字段。
4. **采集与判断分离**：数据管道负责提供事实材料，不直接作出最终投资决定。
5. **支持时点分析**：历史数据设计应避免使用当时尚不可得的信息。
6. **保留数据血缘**：重要数据未来应记录来源、抓取时间、原始字段名、解析器版本、单位及适用日期等信息。
7. **分阶段建设**：每次只实施一个范围明确、能够独立验证的小步骤。

## 公开仓库与隐私边界

本仓库保留对研究、复现和审计至关重要的市场数据、标准化数据、报告与代码；只有凭据、个人身份信息、账户信息和明确标记为私密的输入不会上传。完整规则见 [`PRIVACY.md`](PRIVACY.md)。

## iWencai 数据约束

iWencai 通过自然语言问题返回动态字段，而不是提供固定字段结构。例如：

```text
收盘价[20260807]
总市值[20260807]
市盈率(pe,ttm)[20260807]
```

未来的数据处理层需要保留原始响应和原始字段名，并从字段中识别日期、报告期、单位和口径。理想的数据记录应逐步具备以下血缘信息：

```text
raw_field_name
canonical_field_name
as_of_date
period_end
fetched_at
source
parser_version
unit
adjustment_type
confidence
```

本仓库已实现基础字段名、日期和报告期解析，并已将一次覆盖 5,543 个 A 股证券的历史真实 iWencai 分页查询转换为带字段级血缘的证券主表、日行情和估值快照。财务层已完成历史全 A 股批次的三大报表长表标准化和五项基础比率计算。后续日常采集只覆盖约 3,193 个沪深主板证券；历史全市场 Raw 继续作为不可变证据保留。采集器支持不可变分页保存和中断后续页续采，但尚未建立连续历史更新。

## 分阶段建设路线

1. **仓库基础**：建立目录结构、项目文档和基础配置规范。
2. **原始数据基础设施**：建立原始响应存储、查询日志和时间戳规则。
3. **字段解析层**：处理 iWencai 动态字段及日期、报告期和字段映射。
4. **核心市场数据库**：建设证券主表、日行情和估值快照。
5. **财务数据库**：整理三大财务报表并计算基础财务指标。
6. **事件监控**：跟踪公告、新闻和其他重要公司事件。
7. **投资组合管理**：维护持仓、交易和投资卡片。
8. **筛选系统**：对现有持仓和新机会进行研究优先级排序。
9. **分析与复盘**：开展深度研究、情景估值、红队审查和决策复盘。

## 尚未实现

当前仓库仍不包含：

- 仓库内 API 凭据或自动交易能力；
- 连续历史市场数据库或全市场连续财务数据库；
- 全市场真实高级财务指标、行业中性筛选或估值模型；
- 投资建议、自动下单或自动交易功能；
- 项目依赖和 Python 虚拟环境。

所有后续功能都应通过范围明确、可验证的独立任务逐步加入。
