# Personal Investment Research System

这是一个长期建设的个人投资研究与决策支持系统。项目通过数据工程、结构化研究和投资复盘来提高决策质量，但不用于自动交易。

## 项目目标

系统最终形成以下协作方式：

- **Codex**：负责数据采集、整理、标准化、自动化和报告生成。
- **GitHub**：作为研究资料、数据文件、程序和变更历史的中央仓库。
- **iWencai（同花顺问财）**：作为主要的 A 股数据来源。
- **ChatGPT**：负责结构化投资分析、风险审查和投资委员会辅助。
- **投资者本人**：保留最终投资决策权并负责实际执行。

完整工作流预计为：

```text
数据来源
  ↓
Codex 数据管道
  ↓
GitHub 投资研究仓库
  ↓
结构化投资数据库
  ↓
ChatGPT 投资分析流程
  ↓
投资决策日志与组合复盘
```

## 目录职责

| 目录 | 未来职责 |
| --- | --- |
| `config/` | 配置文件、字段映射和其他规则文件。 |
| `data/raw/` | 保存数据源的原始响应。原始文件必须保留且不得覆盖。 |
| `data/normalized/` | 保存经过清洗和标准化的结构化数据。 |
| `data/derived/` | 保存计算指标、估值分位、风险指标等衍生数据。 |
| `portfolio/` | 保存持仓、交易记录和投资卡片。 |
| `reports/daily/` | 保存自动生成的每日研究报告。 |
| `reports/weekly/` | 保存每周市场和投资组合复盘报告。 |
| `reports/quarterly/` | 保存季度研究和投资组合复盘报告。 |
| `research_queue/` | 保存等待进一步研究的证券和主题。 |
| `decision_journal/` | 保存投资决策及后续复盘记录。 |
| `scripts/` | 保存未来的数据采集、标准化、处理和报告脚本。 |

## 核心设计原则

1. **先保存原始数据**：任何标准化或计算开始前，先完整保存数据源响应。
2. **原始数据不可覆盖**：未来采集的新快照不得破坏已有原始记录。
3. **字段必须可追溯**：iWencai 的原始动态字段名必须能追溯到标准字段。
4. **采集与判断分离**：数据管道负责提供事实材料，不直接作出最终投资决定。
5. **支持时点分析**：历史数据设计应避免使用当时尚不可得的信息。
6. **保留数据血缘**：重要数据未来应记录来源、抓取时间、原始字段名、解析器版本、单位及适用日期等信息。
7. **分阶段建设**：每次只实施一个范围明确、能够独立验证的小步骤。

## 公开仓库与隐私边界

本仓库保留对研究、复现和审计至关重要的市场数据、标准化数据、报告与代码；只有凭据、个人身份信息、账户信息和明确标记为私密的输入不会上传。完整规则见 [`PRIVACY.md`](PRIVACY.md)。

## iWencai 数据约束

iWencai 通过自然语言问题返回动态字段，而不是提供固定字段结构。例如：

```text
收盘价[20260807]
总市值[20260807]
市盈率(pe,ttm)[20260807]
```

未来的数据处理层需要保留原始响应和原始字段名，并从字段中识别日期、报告期、单位和口径。理想的数据记录应逐步具备以下血缘信息：

```text
raw_field_name
canonical_field_name
as_of_date
period_end
fetched_at
source
parser_version
unit
adjustment_type
confidence
```

本仓库已实现基础字段名、日期和报告期解析，并已将一次覆盖 5,543 个 A 股证券的真实 iWencai 分页查询转换为带字段级血缘的证券主表、日行情和估值快照。财务层已完成 5,550 个 A 股证券的 2025 年报分页采集、三大报表长表标准化和五项基础比率计算；采集器支持不可变分页保存和中断后续页续采，但尚未建立定时任务和连续历史更新。

## 分阶段建设路线

1. **仓库基础**：建立目录结构、项目文档和基础配置规范。
2. **原始数据基础设施**：建立原始响应存储、查询日志和时间戳规则。
3. **字段解析层**：处理 iWencai 动态字段及日期、报告期和字段映射。
4. **核心市场数据库**：建设证券主表、日行情和估值快照。
5. **财务数据库**：整理三大财务报表并计算基础财务指标。
6. **事件监控**：跟踪公告、新闻和其他重要公司事件。
7. **投资组合管理**：维护持仓、交易和投资卡片。
8. **筛选系统**：对现有持仓和新机会进行研究优先级排序。
9. **分析与复盘**：开展深度研究、情景估值、红队审查和决策复盘。

## 当前进度

- 第一阶段已完成：基础目录、项目文档和项目配置均已建立。
- 第二阶段已完成：已建立本地 JSON 原始响应保存、不可覆盖保护和查询日志。
- 第三阶段已完成基础验证：可处理日期、报告期、版本化字段映射和未知字段保留，并已审计一份真实响应。
- 第四阶段已完成单日完整范围验证：56 个原始分页覆盖 5,543 个 A 股证券，生成 5,543 条证券主表及 5,539 条日行情和估值记录。
- 第五阶段已完成基础模型验证：贵州茅台、宁德时代和招商银行的 2025 年报及 2026 年一季报生成 6 条报告版本和 90 条三大报表事实，公告日期用于时点可得性控制。
- 第五阶段已完成 2025 年报全市场扩展：56 个原始分页覆盖 5,550 个证券，生成 5,550 条报告版本、83,250 条财务事实及 27,750 条基础财务指标；缺失输入保持为空且有明确状态。
- 2026 年一季报已安全保存第 1—41 页（4,100 条），因当日数据源配额中断，待配额恢复后从第 42 页续采；未将不完整批次发布为标准化数据。
- 第六阶段已建立公告事件监控基础：公告搜索响应原样存档，事件表保留公告时间、可得时间、URL、原始条目和透明分类依据；已用 2 条真实股份回购公告验证。
- 第七阶段已建立隐私安全的组合输入规范：持仓、交易和投资卡有版本化字段、空模板及本地验证器；真实账户数据默认只保存在 Git 忽略的私密目录。
- 第八阶段已建立研究优先级筛选：全市场初筛生成 P0/P1/P2/Reject 队列，持仓复核根据投资者明确维护的 thesis、估值、风险和目标权重状态生成 ADD/HOLD/TRIM/EXIT/REVIEW 候选；两者均不自动交易。

## 尚未实现

当前仓库不包含：

- 自动定时采集任务、仓库内 API 凭据；
- 连续历史市场数据库或全市场连续财务数据库；
- 跨期增长指标、筛选模型或估值模型；
- 投资建议、自动下单或自动交易功能；
- 项目依赖和 Python 虚拟环境。

所有后续功能都应通过范围明确、可验证的独立任务逐步加入。
